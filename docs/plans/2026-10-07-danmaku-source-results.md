# 电影弹幕来源查询与选择

用户要求在找到的电影弹幕中标出来源，避免先显示平台链接、选中后才发现没有弹幕。继续保持单 Python 入口，不操作图形界面。

## 选择

仅给旧下拉框改名仍无法判断可用性；选择时再查询仍需要用户试错。采用选中电影后查询全部已知平台链接，取得并缓存后显示条数。其他相似电影候选保持待查，选中再查询。

## 实现

- `DanmakuSource` 保存平台、已解析评论、实际服务来源、平台 URL、本地缓存路径及失败原因。条数为合成过滤前的有效解析条目。
- `discover_danmaku_sources` 查询当前电影所有支持平台，同时最多三个请求任务；B 站优先直连合并 XML 与全部分段，直连无可用数据时回退公共库；其他平台主库失败后尝试备用库。失败归到对应平台，不阻止其他平台返回结果。
- `ScanResult.source_catalog` 用标题、年份、支持的平台链接及官方匹配偏移作为索引，保存本会话各电影的结果。成功来源保存在本机 `danmaku-平台名*.json`；缓存失败不进入可选列表。
- 2.8.0 本机启用后支持弹弹play官方候选。精确指纹匹配优先，模糊结果先核对片名；多个官方候选需手动选择具体电影或剧集，原平台候选仍可用。官方响应缓存与授权说明见[官方接入](../dandanplay.md)。
- 电影下拉框标出已取得来源与条数，未查询的候选明确标为待查。来源下拉框只显示成功项目，默认按平台顺序选择首个成功来源；下方汇总包含未取得项目，具体原因写日志，不把请求失败当作确定的零条。
- `select_danmaku_source` 直接切换已取得的数据和来源信息，不联网、不读 NAS、不再写重复缓存。换电影前清除旧选择，未查询的候选查询后再选择；已查候选直接复用。
- 「重查来源」重试失败、未完成及部分取得项目，保留完整来源及当前有效选择；部分来源补取失败时保留原数据。来源列表是会话状态，重启后可手动补选已落盘的 JSON。查询结果逐步推送给界面；用户可停止等待并使用已取得结果，取消后的旧消息不会覆盖新结果。
- 查询进度按实际结束的来源数统计，成功项目必须缓存完成；不混合并发下载的字节数，不随等待时间自行增加。

## 验证

本机 105 项非 GUI 自动测试通过；修改既有 GUI 测试以匹配新选择逻辑，留给 CI 执行。新增模拟响应验证所有平台都会查询、条数与缓存一致、前两源失败仍查后续、切换无网络请求、失败重试不重下成功项、跨电影隔离、缓存失败、空结果、并发上限和实际完成数。未调用真实电影接口或操作用户界面。
