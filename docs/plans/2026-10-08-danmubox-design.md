# 弹幕盒子历史归档接入

用户要求将弹幕盒子加入现有“来源”下拉框。2.10.0 沿用已取得才可选择的逻辑：搜索片名时匹配公开历史目录，选中电影后自动核实归档，成功后与官方及平台来源一起列出。

## 数据和选择

- 从 `dmrepository.github.io/list/` 获取分片目录，失败尝试 `dmrepository-list.vercel.app/`。目录用 Windows CNG 解码网站公开的 AES 格式，格式常量来自公开查看器，不是用户凭证。无需新 Python 包或浏览器运行时。
- 验证仓库名、归档路径、大小和目录结构。完整目录缓存 24 小时；分片失败不写入不完整目录，可回用本机旧目录。目录失败只记录原因，原来源继续。
- 根据片名和年份过滤，保留中英文别名及数字片名，排除明显续集和冲突年份。最多取 8 个匹配项，以压缩大小排序，不把大小当作评论数。
- 2.10.1 对用户原始片名和电影服务返回的完整片名、年份分别查询，重复查询组合只处理一次。将命中结果逐一核对后绑定到对应电影，避免“肖申克”等简称被严格归档筛选漏掉；不放宽成任意子串匹配，以免误绑续集。所有查询结束后才判断是否没有匹配归档。
- 归档从 jsDelivr 获取，失败尝试 GitHub raw。沿用压缩包路径、文件数及解压总量限制；7z 使用本机 7-Zip。仅接受一份 XML/JSON 的归档，多文件包提示网页下载后分别补选，不自动混合时间轴。
- 每个归档用 `danmubox:仓库/文件` 标识，与标题、年份和其他来源一起隔离缓存。文件名使用来源 ID 哈希，适配 Windows。归档原名称保留为版本名；统一显示“弹幕盒子（历史归档）”，避免网站平台标签与内容不一致造成误导。

## 界面和故障处理

来源列表显示归档名及实际解析条数，过滤公共源系统提示；合成时继续按现有规则过滤和排版。切换仅使用已取得缓存，后选影片不会丢失归档选择。各版本独立重试，其他成功来源保留；并发仍最多三个来源任务。

状态区对归档使用“可选份数 / 总份数，最多多少条”的简短汇总，完整版本名放在来源下拉框和当前详情，保持日志直接可见。目录查询失败、未匹配、下载失败均给出对应提示，失败不显示为确定的零条。

归档是历史保存量，不保证平台实时完整总量。不同剪辑和上架版本可能时间不同，界面提示核对版本与时间轴。
