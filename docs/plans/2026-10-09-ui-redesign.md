# 字幕弹幕工作台界面整理

用户要求用 baoyu-design 重新设计整个工具界面。基于现有单文件 Tkinter 代码、既有流程和用户对日志常驻的要求，制作可交互 HTML 设计稿，并将对应视觉层次用于实际工具。已询问是否先看设计稿及配色偏好；默认方案为直接改软件并附设计稿，浅灰白背景和青绿强调色，无额外 UI 依赖。

## 操作结构

1. 查找电影：片名搜索优先，影片路径作为可选输入；保留识别、后选影片绑定。
2. 选择资源：原台词字幕、电影候选与弹幕来源紧凑分组；补选和重查仍在对应字段旁。
3. 调整与生成：偏移、密度及弹幕设置集中；生成到本机或写回的主按钮始终在底部。

右侧保留来源状态及运行日志，不用整页滚动。状态与详细日志分开，失败不以颜色作为唯一提示。顶部只放名称、官方接入状态和帮助类入口。长路径和多来源文字需要自动换行。

## 视觉与弹窗

浅灰工作区、白色功能区、细边框；深灰正文、青绿主按钮，其他操作用中性按钮。以统一字体、8/12/16 像素间距建立层次。统一输入框、下拉框、表格、复选项、滚动条、焦点和禁用状态。

弹幕设置、屏蔽规则、官方接入、待写回任务、说明窗口沿用现有行为并统一样式。密钥继续默认遮罩，读取与保存机制不变。不新增导航层级、不更换应用技术栈、不修改网络和合成逻辑。

HTML 原型覆盖查询、资源切换、本机/影片输出、显示设置、规则编辑与测试、接入状态、待写回任务和生成成功状态。明确标为设计稿和示例数据，不读取用户真实密钥，不把模拟操作当作真实下载或生成。

## 验证与交付

不用截图和图片回读。通过隐藏 Tk 测试和浏览器 DOM 检查，核对小屏布局、日志高度、控件可访问性、设置弹窗和原有交互。HTML 版本文件保存在本会话 outputs/designs/subtitle-studio/，通过本地 HTTP 展示。代码改动完整回归后提交推送，等待 GitHub 检查。

## 实施结果

用户已确认直接修改软件并附交互稿，选择浅灰白＋青绿配色。2.12.0 完成三步主表单、右侧来源与日志、底部动作；统一 ttk 控件主题。设置窗口采用 512×288 比例预览与参数并排，规则、接入、待写回及帮助窗口统一标题和主按钮，帮助增加滚动条。保留原查询、凭证、缓存、规则和合成实现。

196 项本机回归通过，新增小屏设置窗口中预览与参数同时容纳、调节后预览更新验证。主窗口既有测试覆盖 1366×768 屏幕、1100×760 窗口及长路径、多来源，日志至少 120 像素。测试只使用隐藏窗口与隔离配置。

交互设计稿入口为 `outputs/designs/subtitle-studio/subtitle-studio-v2.html`（本会话交付目录），保留 v1 供版本回看，元数据登记为待用户审阅。使用 React 18.3.1 和示例数据，明确标识，不读取真实凭证、不请求弹幕、不生成实际字幕。后台 Chromium 通过 1280×668、1366×768、1100×760、1920×1080 和 390×844 的 DOM 尺寸检查，桌面不溢出，窄屏允许纵向滚动且无横向溢出。查询校验、换源、设置、规则编辑与测试、密钥遮罩、模拟生成、影片选择、待写回和键盘关闭弹窗测试通过，无浏览器运行错误。没有读取截图。
